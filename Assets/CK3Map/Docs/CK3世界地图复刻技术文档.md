## 1. 整体地图架构

CK3 世界地图采用分层的数据驱动架构。地形高度、地表类型、行政归属、水系、地图名称和装饰物分别保存，渲染时按照统一的世界坐标合成。

同一地理空间由此支持连续的远近景表达：近景突出山川、地表材质和装饰物，远景突出政治颜色、行政边界与地图名称。镜头移动只改变各层的显示权重，世界的地理结构和行政数据保持一致。

本架构的本质：输入多组描述同一世界的数据，包括地形高度、地表类型、省份归属、水系、边界、名称和装饰物；系统分别把这些数据转换成纹理、网格、材质和场景实例，再按照统一的世界坐标叠加。运行时不需要重新构造世界，只需要根据镜头距离和地图模式调整各层的显示权重，就能在自然地形、政治地图和纸质世界地图之间连续切换。

### 1.1 地图由哪些部分组成

地形层提供完整世界的基础形状，包括平原、丘陵和山脉。

地表层把草地、森林地面、沙漠、岩石和积雪铺到地形上，形成自然地貌的颜色与细节。

政治层把地图位置对应到省份，再沿行政关系得到公国、王国或实际统治者，用于生成政治颜色、边缘渐变和层级边界。

覆盖层包含海洋、湖泊、河流、边界和地图名称。河流沿河道生成形状，边界按行政层级设置宽度，名称沿领土范围排布。

环境层包含近景的树木、城市、城堡和神殿，以及远景的地图纸张、世界外侧手绘区域和桌面。

### 1.2 各类数据在什么阶段发挥作用

各类数据在不同阶段处理，并分别作用于顶点、地表像素、行政区域或场景对象。

地形高度作用于 Mesh 顶点。地形由大量顶点和三角形组成；每个顶点根据自己的世界坐标读取高度，然后改变 Y 坐标。顶点之间的区域由三角形连接，GPU 会自动插值，形成连续山体。

草地、岩石、积雪和政治颜色作用于地形表面。GPU 绘制三角形时处理其覆盖的屏幕像素。Terrain Shader 根据每个像素对应的地图坐标读取地表控制数据和政治颜色，并计算最终颜色。

省份和国家归属在地图构建阶段处理。程序逐像素读取省份图，把颜色转换成省份编号，再结合头衔和历史数据生成法理颜色图与实际领地颜色图。Terrain Shader 在运行时直接读取生成后的颜色图。

河流、边界、水面和地图名称是单独的 Mesh。河流 Mesh 由河道路径生成，边界 Mesh 沿行政区域交界处生成，文字 Mesh 由字体字形沿领土曲线排布生成。它们分别绘制在地形上方，因此可以拥有自己的宽度、形状和材质。

树木和建筑以模型实例为单位处理。每个实例记录世界坐标、旋转和大小；绘制时复用同一份模型，并使用各自的摆放信息。镜头距离控制整批对象的显示强度。

### 1.3 分层数据之间的关系

地理数据定义世界的固定基础，政治数据提供可切换的行政解释，覆盖数据提供具有独立形状的地图元素，环境数据负责远近景氛围。

各层通过世界坐标建立联系。政治地图切换更新归属和颜色；河流宽度由河流数据控制；国名排布由领土形状控制。每个模块独立生成，最终在相同坐标上重合。

### 1.4 在 Unity 中如何组织

CK3 的原版文件首先被转换成 Unity 能直接使用的项目资源。这里主要有三类结果：

- 纹理：保存高度、地表类型、省份范围、政治颜色和水体信息。
- 网格：保存地形、河流、水面、边界和文字的形状。
- 材质：规定这些形状最终显示成泥土、水面、边界线或文字。

转换完成后，这些资源被放入 Unity 场景。场景对象负责引用、摆放和显示资源；运行时负责镜头移动、地图模式切换以及远近景变化。

编辑状态和运行状态引用同一组地图资源。材质颜色或水面参数发生变化后，可以直接在 Scene 窗口观察结果。

### 1.5 近景与远景如何连接

近景地形和远景政治地图位于同一个场景。镜头拉远时，山脉逐渐变平，政治颜色逐渐增强，树木和建筑逐渐淡出，国家名称变得清晰，地图外侧的纸张和桌面进入视野。

这些变化使用同一个镜头距离作为依据，并在一段范围内平滑发生。水面、文字和地形共享相同的过渡进度，从而保持空间重合。

## 2. 完整世界地形网格

本质：使用一份固定的 33×33 网格模板作为地形采样框架，再根据 nodes.dat 将它以不同位置和尺寸重复铺满整个世界。每个顶点按自己的世界坐标读取高度图，形成实际山脉起伏；LOD 不改变单块网格的结构，而是用更多、更小的同类网格替换较大的地形块，从而在需要的位置提高顶点密度。

### 2.1 技术方案与采用原因

世界采用分块结构，是为了用不同数量的网格覆盖同一片区域。远景时，一块 `33×33` 网格覆盖较大区域；提高精度时，这块父节点停止绘制，并由四块同样为 `33×33` 的子节点覆盖原来的区域。继续提高精度，就继续把每个子节点替换成四块更小的节点。

因此，LOD 提升的实质是增加 `33×33` 网格实例的数量，而不是增加单个 Mesh 的顶点数。所有地形块内部结构相同，项目只需要保存一份 Mesh 模板；每个实例提供自己的位置和尺寸。这样可以获得以下结果：

- 每块地形可以单独判断是否位于相机视野内。
- 同一片区域可以用少量大块或更多小块覆盖。
- 所有节点共用同一顶点和三角形结构，只保存一次 Mesh。
- 相邻节点拥有完全一致的边缘顶点排列，便于无缝拼接。
- 地形高度保留在高度图中，网格模板只负责提供采样点。

具体生成顺序如下：

1. 创建一块水平的 `33×33` 顶点网格。
2. 读取 `nodes.dat`，得到每个地形块的位置、尺寸以及它是否位于有效地图范围内。
3. 为每个有效地形块创建一个 Renderer，并让它们共用同一份网格和地形材质。
4. Shader 根据地形块的位置和尺寸，把网格顶点换算到完整世界中的对应位置。
5. 每个顶点在高度图中读取高度，并把高度写入 Y 坐标。
6. 相邻地形块沿边缘拼接，组成完整世界。

前四步建立世界分块并提供顶点，第五步才根据高度数据形成山脉起伏。Mesh 负责地形的采样密度，高度图负责实际地形形状。

### 2.2 高度图与 `nodes.dat` 分别负责什么

高度图是一张灰度图。每个像素只保存一个高度值，用于决定某个位置的地面有多高。它不负责决定世界应该切成多少块，也不记录每块网格使用什么精度。

`game/map_data/nodes.dat` 是原版保存的地形分块表。每条有效记录描述一块地形：

- 地形块左下角的位置。
- 地形块覆盖范围的大小。
- 地形块是否位于实际地图范围内。

原版把这些地形块组织成四叉树，也就是为每个大块记录四个更小的子块。显示父节点时不显示它的四个子节点；显示四个子节点时不再显示父节点。按照观察距离选择父节点或子节点称为 LOD。

CK3 原版可以只细分需要更高精度的四叉树分支。靠近镜头或地形误差较大的区域使用更多小块，较远区域继续使用少量大块，所以同一帧可以同时存在不同尺寸的节点。

本文的 Unity 场景统一选择第 7 层，所有区域使用同样大小的节点，镜头移动时不替换层级。第 7 层把实际世界分成横向 72 块、纵向 36 块，共 2592 个有效地形块。如果全图统一切换到更高层级，覆盖完整世界所需的 `33×33` 网格实例也会成倍增加。

在这套固定层级方案中，`nodes.dat` 用于取得这 2592 块地形的位置、尺寸和有效范围。理论上固定规则网格的位置也可以直接计算，但读取 `nodes.dat` 能够保持原版分块结构，并保留切换到动态 LOD 所需的节点数据。

Unity 构建器读取指定层级的节点记录，跳过实际世界矩形之外的空节点，再取得每个有效节点的左下角和尺寸。它们按原版 Terrain Shader 的实例参数格式编码后传给当前节点。动态 LOD 使用的第四个插值分量在固定第 7 层场景中为 0。

### 2.3 共享的 `33×33` 网格

每块地形使用 `33×33=1089` 个顶点。33 个顶点之间形成 32 段，因此一块地形包含 `32×32` 个小方格，每个方格由两个三角形组成。

共享 Mesh 使用 0 到 1 的局部坐标：

```text
左下角：(0,0)
右下角：(1,0)
左上角：(0,1)
右上角：(1,1)
```

每个地形块另外提供世界起点和世界尺寸。顶点的世界位置按下面的关系得到：

```text
顶点世界位置 = 地形块起点 + 顶点局部位置 × 地形块尺寸
```

例如一块地形从世界坐标 `(1280,768)` 开始，宽和高都是 128，那么局部中心点 `(0.5,0.5)` 对应世界坐标 `(1344,832)`。Shader 使用 `(1344,832)` 查询高度图，从而得到这个顶点的 Y 坐标。

所有地形块共用同一 Mesh，是因为 Mesh 只表示“一块地形内部怎样排列顶点”。地形块在世界中的位置由单独参数决定，不需要为每块地形复制一份相同顶点数据。

所有 LOD 都使用相同的 `33×33` 网格。下面以一块第 7 层区域为基准，说明提高 LOD 时怎样增加网格实例：

| 使用层级 | 单块世界尺寸 | 相邻顶点间距 | 覆盖同一片区域需要的网格数 |
|---:|---:|---:|---:|
| 7 | 128 × 128 | 4 | 1 |
| 8 | 64 × 64 | 2 | 4 |
| 9 | 32 × 32 | 1 | 16 |
| 10 | 16 × 16 | 0.5 | 64 |

第 7 层用一块 `33×33` 网格覆盖该区域；第 8 层用四块；第 9 层用十六块；第 10 层用六十四块。网格数量增加后，同一片区域拥有更多顶点，高度图中的细节才能表现出来。

Unity 场景固定使用第 7 层时，顶点间距为 4 个世界单位。启用动态 LOD 时，相机附近可以把第 7 层父节点逐级替换为第 8 至第 10 层子节点，远处则继续保留较少的大节点。

共享网格最关键的部分，是把 `33×33` 的行列编号转换成 0 到 1 的节点局部坐标。顶点先量化为 16 位归一化数，再还原为浮点数，以保持原版节点输入精度。随后每四个相邻顶点连接成两个三角形，行列奇偶决定对角线方向。

这部分实现在 `Editor/CK3TerrainNodeMeshBuilder.cs` 的 `Build` 方法中；裙边模板由同一文件的 `BuildSkirt` 与 `AppendSkirtPair` 生成。

### 2.4 高度采样与地形拼接

Terrain Shader 先计算顶点的世界 XZ 坐标，再用这个坐标读取高度。高度值写入顶点的 Y 坐标后，水平网格就形成了地形起伏。

相邻地形块使用相同的边界坐标。左侧地形块最右一列顶点与右侧地形块最左一列顶点位于相同世界位置，也会读取高度图中的相同位置，因此两侧边缘能够接在一起。

共享网格中 0 到 1 的局部坐标先乘以当前节点尺寸，再加上节点起点，得到节点在四叉树中的位置；随后换算成完整世界的 XZ。高度查询使用这个 XZ 读取第三章介绍的高度页表，最后将 XZ 与高度组合成三维世界坐标。

这条顶点处理路径位于 `Shaders/CK3TerrainSurface.shader` 的 `VertexMain`。高度页表查询由同一 Shader 的 `CK3GetHeight` 完成。

同一段 Shader 也处理裙边和平面地图过渡。裙边 Mesh 在每个外围位置保存两个完全重合的顶点，顶点编号一奇一偶；`_CK3IsSkirt` 启用后，其中一个保持地表高度，另一个增加负的 `_CK3SkirtSize`，两者之间的三角形形成向下侧面。`_FlatMapLerp` 则在远景阶段把地形高度逐渐插值到统一平面高度。

每块地形外围还生成一圈向下延伸 5 个世界单位的侧面，称为裙边。裙边用于遮住不同精度地形块相邻时可能出现的细缝。每个边缘位置需要一个顶部顶点和一个底部顶点，128 个边缘位置因此生成 256 个裙边顶点。

```text
地形表面 ──────────┐
                   │ 裙边向下延伸
                   │
```

裙边只负责遮挡缝隙，地形的连续性仍由相邻块使用相同坐标和相同高度数据保证。

### 2.5 Unity 中的实现结果

编辑器先生成一份共享的地形 Mesh 和一份裙边 Mesh，然后读取 `nodes.dat`，在 Scene 中创建 2592 个地形块。每块地形保存自己的起点和尺寸，并引用相同的 Mesh 与 Material。

每个地形对象引用同一个 `terrainMesh` 和 `terrainMaterial`。对象自身的 Transform 负责把 Unity 的空间包围盒放到正确地区；节点的真实起点、尺寸和裙边标志通过 `MaterialPropertyBlock` 单独传给 Shader。

如果直接修改共享 Material，最后写入的节点参数会覆盖其他所有地形块。`MaterialPropertyBlock` 允许 Renderer 继续共享同一 Material，同时让每个 Renderer 携带不同的节点参数。Transform 与 Shader 计算出的世界区域必须一致，否则 Unity 会根据错误的空间包围盒提前裁掉节点，出现地图只在特定角度或距离可见的问题。

场景节点创建位于 `Editor/CK3TerrainWorldBuilder.cs` 的 `CreateRenderer`；实例参数绑定位于 `Runtime/CK3TerrainNodeBinding.cs` 的 `Apply`。

绘制时，Shader 根据地形块参数把局部网格放到世界中的正确区域，再从高度图读取每个顶点的高度。Unity 同时为每块地形保存空间范围，以便相机只绘制视野中的地形块。

最终数据关系如下：

```text
共享 33×33 Mesh：提供顶点排列
nodes.dat：提供每块地形的位置和尺寸
高度图：提供每个顶点的 Y 坐标
Terrain Shader：把三者组合成最终地形
裙边 Mesh：遮挡地形块之间的细缝
```

### 2.6 分块方案的收益与代价

这套方案最主要的收益来自 LOD 和分块裁剪。

#### 减少远景顶点数量

同一片区域在近景可以由 64 个小节点覆盖，在远景只保留 1 个大节点。每个节点都是 1089 个顶点，因此该区域从近景到远景可以由约 7 万个顶点减少到 1089 个顶点。远处保留过高密度的顶点无法增加肉眼可见细节，只会增加 GPU 顶点处理量。

#### 按区域进行相机裁剪

世界被拆成独立节点后，Unity 可以整块排除相机视野外的区域。镜头观察欧洲时，位于视野外的亚洲节点无需提交给 GPU。单一巨大 Mesh 只能整体判断可见性，只要其中一小部分进入画面，整个对象就仍然处于可见状态。

#### 减少 Mesh 资源的重复存储

所有节点共用一份 `33×33` Mesh。项目只保存 1089 个模板顶点和一套索引，而不是为数千个地形块分别保存相同的顶点排列。每个节点只增加位置、尺寸等少量参数。

#### 保持统一的边缘结构

所有节点的四条边都使用相同的 33 个顶点位置。相邻节点更容易共享边界坐标，LOD 过渡和裙边也可以使用统一规则。

#### 共享 Mesh 不等于自动合批

共享 Mesh 和 Material 可以减少资源切换，并为 GPU Instancing 提供基础，但它本身不会自动把所有节点变成一次 Draw Call。每个普通 MeshRenderer 仍可能产生独立绘制提交。真正减少 Draw Call 还需要启用兼容的 GPU Instancing、BatchRendererGroup 或专用地形批处理。

因此，这套结构首先解决的是顶点数量、可见性裁剪和资源复用，合批属于可以继续叠加的优化。

#### 代价

分块也会增加系统复杂度：

- 节点数量较多，会增加 Scene 对象、Renderer 和 Bounds 管理成本。
- 粗细节点相邻时可能出现裂缝，需要裙边和 LOD 顶点过渡。
- LOD 切换条件不合理时，会出现明显的地形跳变。
- 节点 Bounds 错误时，Unity 会错误裁掉仍在画面中的地形。
- 固定使用较低 LOD 虽然结构简单，但近景地形会因顶点间距过大而显得粗糙。

CK3 的方案是在这些代价之上换取完整世界地图的可裁剪、可变精度和可复用网格结构。

## 3. 高度页表与地形形变

本方案的本质：先把完整高精度高度图按区域切成不同精度的小块，再把这些高度块集中打包到压缩高度图中，并用一张页表记录每个世界区域对应的高度块位置和精度。Shader 查询高度时，先通过世界坐标读取页表，再跳转到压缩高度图取得实际高度，最终把水平网格顶点抬升到对应的 Y 坐标。

第二章中的地形块只是一组水平网格。本章负责把每个顶点的世界 XZ 坐标转换成高度 Y，最终形成山脉和平原。

最直接的方案是让 Shader 读取完整高度图。CK3 没有直接使用这张大图，而是先把高度图拆成许多小块，再按不同精度打包到一张较小的纹理中。另一张小纹理记录每个世界区域应该去哪里寻找自己的高度块。这种“索引图 + 数据图”的组合就是高度页表。

Unity 中的高度资源构建入口是 `Editor/CK3TerrainHeightBuilder.cs` 的 `Build`；顶点查询集中在 `Shaders/CK3TerrainSurface.shader` 的 `CK3GetHeight`。正文只解释两者之间的数据关系。

### 3.1 原版高度数据为什么采用页表

原始 `heightmap.png` 是一张 16 位灰度图。每个像素保存一个 0 到 65535 的高度值，完整尺寸为 `18432×9216`。它的采样密度很高，但并不是所有地区都需要保留同样多的高度样本。平坦地区可以使用较低精度，复杂山地则需要较高精度。

原版把高度图按区域切块，并允许每块选择五种精度之一。高精度块保留更多样本，低精度块只保留少量样本。选好的小块被集中排进 `packed_heightmap.png`，即压缩高度图。

压缩以后，世界中某个位置已经无法直接用同一坐标读取 `packed_heightmap.png`，因为它所属的小块可能被搬到了压缩图中的其他位置。`indirection_heightmap.png` 用来记录这种对应关系：先查它得到高度块在压缩图中的位置和精度，再去压缩图读取真正高度。

两张纹理的职责可以概括为：

```text
indirection_heightmap：这一片世界的高度数据存放在哪里、使用哪种精度
packed_heightmap：真正的高度数值
```

“页表”这个名称来自虚拟内存中的相同思路：使用一张较小的表，把逻辑位置转换为数据的实际存储位置。

### 3.2 Packed Heightmap 与 Indirection Heightmap

完整世界首先被分成 `288×144` 个高度区域。每个区域在最高精度下包含 64×64 个高度间隔。为了让相邻区域共享边界，实际存储时还要保留末端的一行和一列，因此基础高度块为 `65×65` 个样本。

五种高度块精度如下：

| 压缩层级 | 每块保存的样本尺寸 | 含义 |
|---:|---:|---|
| 0 | 65×65 | 保留完整精度 |
| 1 | 33×33 | 每隔一个原始样本保存一次 |
| 2 | 17×17 | 每隔三个原始样本保存一次 |
| 3 | 9×9 | 进一步降低平坦区域精度 |
| 4 | 5×5 | 最低精度 |

这里始终多出的 1 个样本用于保存高度块的右边界和上边界。例如 64 个高度间隔需要 65 个采样点。这个共享边界使相邻块能够在边缘读取相同高度。

`indirection_heightmap.png` 的每个像素对应一个高度区域。它的四个颜色通道不是画面颜色，而是四项索引数据：

- R、G：该区域的高度块位于压缩高度图中的什么位置。
- B：当前高度块相对于完整 65×65 块缩小了多少。
- A：使用第几个压缩层级，以及应该使用压缩图中的哪一组布局参数。

`packed_heightmap.png` 把所有实际使用的高度块排列成一张大图。不同压缩层级分区存放，`heightmap.heightmap` 中的 `level_offsets` 记录每个层级在压缩图中的起始位置。

Unity 构建后保存两张运行纹理：压缩高度使用 R16 格式，保留 16 位高度精度；间接寻址图使用 RGBA32 格式，保留四个 8 位索引通道。

### 3.3 世界坐标到高度页的寻址算法

一次高度查询分成“找到高度块”和“在高度块中采样”两段。

第一步，把顶点的世界坐标转换为整张地图中的比例。世界宽 9216、高 4608，因此：

```text
地图比例 X = worldX / 9216
地图比例 Y = worldZ / 4608
```

第二步，用这个比例定位 `288×144` 页表中的像素。页表使用 Point 过滤，也就是只读取一个确定像素，避免相邻页面的索引值被插值混合。

第三步，从页表像素的 RGBA 得到压缩高度块的位置与精度。精度决定当前块是 65、33、17、9 还是 5 个样本宽。

第四步，计算顶点在当前高度区域内部的位置。例如顶点位于该区域横向 25%、纵向 60% 的位置，就在选中的高度块内部使用同样比例寻找样本。

第五步，把“高度块在压缩图中的起点”和“块内位置”相加，得到 `packed_heightmap.png` 的最终采样坐标。块边缘会加入半个纹素的偏移，采样范围也限制在该块的有效区域内，避免线性过滤读到旁边另一块的高度。

第六步，用 Bilinear 过滤读取压缩高度。Bilinear 会在周围四个高度样本之间插值，使顶点移动时高度连续。

完整路径为：

```text
世界 XZ
  → 页表中的区域坐标
  → 读取该区域的高度块位置与精度
  → 计算高度块内部坐标
  → 压缩高度图坐标
  → 读取高度
```

地图左右边缘不进行环绕连接，超出范围的坐标会被限制在有效地图边缘。

### 3.4 高度解码与世界 Y 坐标

压缩高度图的 R 通道是 0 到 1 的归一化数值。CK3 世界高度范围为 50，因此顶点高度为：

```text
worldY = packedHeight.r × 50
```

材质中还提供整体垂直偏移，用于统一调整地形位置：

```text
worldY = packedHeight.r × 50 + terrainVerticalOffset
```

Terrain Shader 在第二章得到顶点的世界 XZ 后调用高度查询，再把结果写入 Y：

```text
顶点最终位置 = (worldX, worldY, worldZ)
```

原始 16 位高度意味着高度范围 0 到 50 被分成 65535 个数值等级，单级高度差约为 `50/65535`。Unity 使用 R16 纹理保存压缩高度，避免转换成普通 8 位图片后产生明显台阶。

Unity Project 窗口中直接导入的 `heightmap.png` 可能因为 Texture Importer 的 Max Size 显示为 2048×1024，这只是 Unity 生成的预览纹理尺寸。高度构建器直接解码原版 PNG，并把运行所需的 `packed_heightmap.png` 保存为原始尺寸的 R16 资产，不使用缩小后的预览高度图。

### 3.5 地形法线计算

顶点高度决定地形形状，光照还需要知道表面朝向。这个朝向称为法线。平地法线朝上，斜坡法线会向坡面外侧倾斜。

Terrain Shader 在当前世界位置的左、右、下、上各读取一次高度：

```text
hLeft  = Height(x - step, z)
hRight = Height(x + step, z)
hDown  = Height(x, z - step)
hUp    = Height(x, z + step)
```

左右高度差表示 X 方向坡度，上下高度差表示 Z 方向坡度。当前实现按原版参数构造法线：

```text
normal = normalize(
    (hLeft - hRight) × 0.8,
    2,
    (hDown - hUp) × 0.8
)
```

相邻采样间距 `step` 为 1.6 个世界单位，坡度缩放为 0.8。最终归一化把向量长度变为 1，只保留方向。地形光照使用这条法线计算山坡的明暗变化。地表材质自身的细小凹凸属于第四章的材质法线，不改变这里的宏观山体坡度。

### 3.6 Flat Map 高度压平

相机拉远进入平面地图状态时，山脉不会瞬间消失，而是逐渐压向统一高度。Shader 使用线性插值：

```text
finalY = lerp(terrainY, 3.92, flatMapLerp)
```

`flatMapLerp` 从 0 变化到 1：

- 0：保留完整地形高度。
- 0.5：地形高度向平面收缩一半。
- 1：所有顶点位于 Y=3.92，地形成为平面地图。

这一步在顶点完成，因此仍然使用同一批地形 Mesh。水面、河流和地图名称也要使用相同的压平进度，才能在过渡过程中继续贴合地形。

### 3.7 页表方案的收益与代价

高度页表的主要收益是减少高度纹理体积和采样带宽。原始高度图的像素数量约为压缩高度图的 13 倍；平坦地区使用低精度块后，不需要为它们保存与山地相同数量的高度样本。

分块结构也与第二章的地形 LOD 相配合。远景节点顶点较少，高度数据中的平坦区域也可以使用较低精度；复杂地区仍然保留细节。所有贴地系统通过相同查询函数取得高度，地形、河流和地图名称能够共享同一高度基准。

代价是一次高度查询需要先读取页表，再读取压缩高度图，比直接读取单张高度图多一次纹理访问。页表必须使用 Point 过滤，压缩高度必须使用 Bilinear 过滤；通道解释、层级偏移、半纹素边界或坐标方向任一项错误，都会导致整块高度错位或在页面边缘形成接缝。

压缩高度图也不适合直接手工编辑。地形修改通常应先作用于完整高度数据，再重新执行分块和打包，保持页表与压缩高度块一致。

## 4. 地表材质合成

本质：系统不为整个世界保存一张超高分辨率最终贴图，而是用控制图为每个世界位置选择最多四种可重复平铺的材质，再根据权重和材质内部的高度遮罩重新计算混合比例，合成颜色、细节法线和反光属性，最后叠加覆盖全世界的宏观色调。它本质上是“世界位置决定材料组合，平铺纹理提供近景细节，宏观颜色提供远景综合色调”的多尺度地表合成方案。

地形网格和高度图只决定地面的几何形状。例如高度图可以形成阿尔卑斯山的山峰，却没有记录山坡表面是草地、裸岩还是积雪。地表外观由另一套材质系统完成。

最直接的做法是为整个世界制作一张最终彩色贴图，但这种方法无法同时满足远景和近景。整张世界缩进屏幕时，它可以表现大陆综合色调；镜头靠近后，同一张贴图的像素会被放大，草叶、砂砾和岩石裂纹会变得模糊。若把整张世界贴图提高到足以表现近景细节的分辨率，纹理尺寸和显存占用又会急剧增加。

CK3 因此把地表外观拆成两个尺度：

- 105 套可重复平铺的地表材质负责近景细节。每套材质描述一种草地、泥土、沙地、岩石或积雪自身的颜色、凹凸和反光特征。
- 覆盖完整世界的控制图负责说明这些材料分布在哪里，但不保存草叶或石纹等细节。
- 覆盖完整世界的宏观颜色图负责大陆尺度的冷暖、明暗和地域色调。

这里的“控制图”是与世界地图对齐的数据纹理。可以把它理解为一张覆盖整个世界的表格：纹理中的每个像素对应世界中的一小块矩形区域，像素的 RGBA 四个通道用于保存四项数据。它不是最终显示到画面上的彩色图片，而是供 Shader 查询的材料分布数据。

CK3 使用两张控制图：

| 控制图 | RGBA 四个通道保存的内容 |
|---|---|
| `detail_index.tga` | 当前地图位置可以使用的四个材质编号 |
| `detail_intensity.tga` | 上述四种材质各自的初始权重 |

例如 `detail_index.tga` 某个像素的四个通道可以保存 `(12,37,64,8)`，表示这个地图位置使用第 12、37、64、8 号材质；`detail_intensity.tga` 同一位置保存 `(0.55,0.20,0.20,0.05)`，表示它们的初始比例分别为 55%、20%、20% 和 5%。材质编号具体对应草地、泥土还是岩石，由 `materials.settings` 中的材质排列决定。

世界位置与控制图位置按整张地图的宽高进行换算。假设世界宽度为 `9216`、高度为 `4608`，正在绘制的地表位置为 `(世界 X, 世界 Z)`，则它在控制图中的归一化位置为：

```text
控制图 U = 世界 X / 9216
控制图 V = 世界 Z / 4608
```

Shader 使用这个 UV 查询两张控制图。相邻世界位置会查询控制图中的相邻像素，并在材料相同的前提下平滑过渡权重。因此“一个地图位置”不是一个省份、一个地形块或一个 Mesh 顶点，而是当前正在绘制的地表像素所对应的世界坐标。

105 套材质不会在一个位置同时计算。控制图为当前世界坐标选出最多四套候选材质，并给出它们的初始占比。Shader 随后只读取这四套材质，将它们混合成该位置的近景地表。

例如，假设当前正在绘制的地表像素对应世界坐标 `(4200,1800)`。换算到控制图后，该位置的材质编号对应草地、泥土、岩石和积雪，初始比例为：

```text
草地：55%
泥土：20%
岩石：20%
积雪：5%
```

这组比例只表示四种材料在该区域中的初始竞争关系，并不表示最终像素一定是四种颜色的简单平均。

每套漫反射纹理的 Alpha 通道还保存一张“材质高度遮罩”。它用 0 到 1 的灰度表示这张材质纹理内部的相对高低，例如岩块顶部可以接近 1，石缝可以接近 0。这个数值只用于混合材料，不会改变地形 Mesh，也不是第三章的山脉高度。

“高度混合”就是利用这张材质高度遮罩重新计算四种材料权重的算法。初始权重相近时，遮罩值较高的纹理结构优先显示，遮罩值较低的部分仍可保留下面的材料。因此岩石与泥土交界处可以先出现凸起岩面，石缝中继续露出泥土，而不是得到一条均匀模糊的半透明渐变。具体的权重计算公式见 4.3 节。

这项计算发生在地形三角形覆盖的每个屏幕像素上，不是只在 Mesh 顶点上执行。对于其中一个屏幕像素，处理顺序如下：

1. 用该像素对应的世界 XZ 坐标查询控制图，取得四个材质编号和初始权重。
2. 用四个编号从材质纹理数组中读取四套材质。数组中的每一层就是一套可平铺材质。
3. 读取四套材质的颜色与材质高度遮罩，并通过 4.3 节的高度混合算法求出最终权重。
4. 使用同一组最终权重混合四套材质的颜色、细节法线和反光属性。
5. 用宏观颜色图调整合成地表的大范围色调。例如同一种草地在湿润地区可以偏深绿，在干燥地区可以偏黄，但近景草叶纹理仍来自同一套可平铺材质。
6. 把地形坡面的整体朝向与材质提供的细小凹凸结合，再根据太阳、阴影、环境光、粗糙度和高光强度计算最终亮度与反射。

三组材质纹理数组在流程中各自提供不同信息：

| 材质数据 | 保存内容 | 在山麓示例中的作用 |
|---|---|---|
| 漫反射/高度数组 | RGB 保存材料颜色，Alpha 保存材质高度遮罩 | 提供草色、泥色、岩色和雪色，并影响不同材料在交界处谁优先显露 |
| 法线数组 | 保存材料表面细小方向变化 | 让岩石裂纹、土粒和草地细节对光线产生细小明暗，而不改变山体轮廓 |
| 属性数组 | 保存宏观颜色抑制、高光、金属度和粗糙度 | 决定泥土是否暗哑、岩石高光是否集中，以及材料受宏观色调影响的程度 |

因此，最终画面不是七份数据按固定顺序简单叠图，而是先选择材料、再求混合比例、然后合成材料属性，最后统一计算颜色和光照：

```text
世界位置
  ├─→ 索引控制图：选择最多四套材质
  └─→ 权重控制图：取得四套材质的初始比例
                  ↓
        读取四层颜色、材质高度遮罩、法线和属性
                  ↓
        高度混合：求出四层最终比例
                  ↓
        合成近景颜色、细节法线和反光属性
                  ↓
        宏观颜色图调整地域综合色调
                  ↓
        地形坡度 + 细节法线 + 光照参数
                  ↓
                 最终地表
```

材质数组与控制图由 `Editor/CK3TerrainMaterialBuilder.cs` 构建；上述逐像素合成集中在 `Shaders/CK3TerrainSurface.shader` 的 `CK3CalculateDetails`，最终光照位于 `CK3CalculateMapLighting`。

### 4.1 原版材质索引与权重数据

`game/gfx/map/terrain/materials.settings` 是地表材质清单。每个条目包含三张主要纹理：

| 纹理 | 保存的内容 | 用途 |
|---|---|---|
| `diffuse` | RGB 为地表颜色，Alpha 为材质高度遮罩 | 表现草叶、沙粒、泥土和岩石颜色；Alpha 用于重新计算材料混合权重 |
| `normal` | 压缩后的法线方向 | 表现不会改变地形轮廓的细小凹凸 |
| `material` | R 为宏观颜色影响抑制，G 为高光强度，B 为金属度，A 为感知粗糙度 | 控制宏观着色和光照反射 |

这些纹理都是 `1024×1024` 的可平铺纹理。它们只描述一种材料自身的外观，不记录这种材料位于世界上的什么位置。例如草地纹理可以被欧洲、草原和河谷共同使用，具体分布由控制图决定。

Unity 把 105 张同类纹理分别装入三个 `Texture2DArray`。`Texture2DArray` 可以理解为许多尺寸和格式相同的纹理按层叠放在一起；Shader 使用一个整数层号选择其中一张。三个数组保持相同顺序，因此材质编号 27 会同时选择：

```text
漫反射/高度数组的第 27 层
法线数组的第 27 层
属性数组的第 27 层
```

`detail_index.tga` 和 `detail_intensity.tga` 决定材质在世界上的分布。两张图都使用 RGBA 四个通道，每个地图位置最多保存四层材料：

```text
detail_index.RGBA     = 四个材质编号
detail_intensity.RGBA = 四个编号各自的初始权重
```

例如某处控制数据为：

```text
材质编号：(12, 37, 64, 0)
初始权重：(0.65, 0.25, 0.10, 0)
```

表示这里主要是第 12 号材质，同时混入第 37 和第 64 号材质。编号 0 的第四层权重为零，不参与最终画面。

索引图必须使用 Point 过滤。材质编号是离散整数，编号 12 与 13 之间不存在“12.5 号材质”；让 GPU 直接对索引做线性过滤，会得到原本没有指定的错误编号。权重则可以插值，但插值时必须先确认相邻位置指向同一种材质。

### 4.2 四层地表材质选择

Shader 根据正在绘制的地表像素所对应的世界 XZ 坐标，定位控制图中的位置。这里的“地表像素”是地形三角形经过光栅化后覆盖的一个屏幕像素，不是 Mesh 顶点，也不是一个省份。相邻屏幕像素可以读取不同的材质组合，因此材质边缘能够比地形网格本身更细。

控制图一个像素只保存四个材质编号。如果只读取最近的一个控制像素，移动镜头时材质分界会沿控制图像素边缘跳变。CK3 因此读取当前位置周围的四个控制像素，并根据位置在这个小方格中的比例计算四个空间权重：

```text
左下权重 = (1-x) × (1-y)
右下权重 = x × (1-y)
左上权重 = (1-x) × y
右上权重 = x × y
```

其中 `x` 和 `y` 是当前位置在一个控制像素方格内的横向与纵向比例，范围都是 0 到 1。

四个相邻控制像素各自又可能包含四个材质编号。Shader 以左下控制像素的四个编号作为当前四层，只把其他三个控制像素中编号相同的权重累加到对应层。这样既获得空间上的平滑变化，又不会对材质编号本身进行插值。

得到四个编号和初始权重后，Shader 按编号从三个纹理数组中取出对应层。每种材质可以在 `materials.settings` 中设置独立的 `tile_factor`，用于控制纹理在世界宽度上重复多少次。细沙和碎石可以使用较密的平铺，大片土壤可以使用较疏的平铺。

材质纹理坐标直接由世界位置计算：

```text
材质 UV = (世界 XZ + 平铺起点偏移) × 当前材质的平铺系数
```

这种世界空间平铺不会因地形被切成多个节点而重新开始。相邻地形块在同一个世界位置得到相同 UV，所以草地、沙地和岩石纹理能够连续跨过地形块边界。

纹理数组使用 Repeat 寻址、Trilinear 过滤和 Mipmap。Repeat 使纹理可以连续平铺；Mipmap 会在远处改用预先缩小的纹理层，减少密集细节产生的闪烁和摩尔纹。

### 4.3 材质高度遮罩与权重重算

初始权重只能描述材料在平面上各占多少。如果直接按权重混合颜色，岩石、泥土和草地会形成均匀的半透明渐变，交界处容易像一层污泥。

CK3 在每张漫反射纹理的 Alpha 通道中保存材质高度遮罩。这里的“高度”是混合算法使用的相对值，不是世界单位，也不会移动地形 Mesh。它只表示同一张平铺纹理内部哪些图案应被视为较高、哪些应被视为较低。例如石块顶部可以使用较高数值，石缝可以使用较低数值。

高度混合不是把四种材料真的沿 Y 轴堆叠，而是把“初始权重”和“材质高度遮罩”共同作为竞争条件，重新计算当前像素最终应保留多少草地、泥土、岩石或积雪。

Shader 先把每层当前采样点的材质高度遮罩值与初始权重相加：

```text
竞争值 = 材质高度遮罩值 + 初始权重
```

然后找出四层中的最大竞争值，并只保留接近最大值的一段范围：

```text
起始值 = 四层最大竞争值 - 混合范围
保留值 = max(竞争值 - 起始值, 0)
最终权重 = 保留值 / 四层保留值之和
```

结果是较高的纹理结构会优先从另一种材料中露出。例如岩石与泥土过渡时，岩石顶部先出现，较低的缝隙仍然保留泥土；积雪与山石过渡时，雪可以先覆盖低洼区域，而凸起岩面继续可见。

`settings.terrain` 中的 `detail_blend_range` 控制竞争范围，原版值为 `0.25`。范围较小会让优势材质迅速覆盖其他层，边缘更明确；范围较大会允许更多层同时保留，过渡更宽、更柔和。

高度混合得到的最终权重同时用于漫反射、法线和材质属性。三组纹理因此在边界处保持一致，不会出现颜色已经变成岩石、粗糙度却仍然属于泥土的错位。

### 4.4 宏观颜色与近景细节

可平铺材质负责近景细节，但重复纹理无法单独表现整个地区的综合色调。如果只铺沙地纹理，北非从近处看有沙粒，远处却会变成颜色完全一致的大面积重复图案。

`colormap.dds` 是覆盖整个世界的宏观颜色图。它不替代草地或沙地纹理，而是在四层材质混合完成后调整大范围颜色。Shader 使用世界位置在整张地图中的比例读取宏观颜色，并翻转纹理 Y 方向，使原版纹理坐标与 Unity 世界 Z 方向一致。

近景材质颜色与宏观颜色使用 Soft Light 混合。Soft Light 会在保留底层纹理明暗细节的同时改变综合色调：宏观图较亮的区域提亮底层，较暗的区域压暗底层，中性灰附近基本保持原色。它比直接相乘更不容易把暗部压黑，也比普通线性插值更能保留沙粒、草叶和石纹。

属性纹理的 R 通道控制当前材料抵抗宏观颜色覆盖的程度：

```text
宏观颜色强度 = (1 - 属性纹理.R) × 全局宏观颜色强度
```

R 越高，材料越接近自身纹理颜色；R 越低，地区宏观色调的影响越强。这样可以让某些材料接受明显的地域着色，同时保护需要稳定颜色的岩石、积雪或特殊地表。

近景与远景分别依赖不同尺度的信息：

- 近距离主要看到 1024×1024 平铺材质中的颜色细节、材质高度遮罩形成的交界和粗糙度变化。
- 远距离看不到单个沙粒或草叶，但仍能看到 `colormap.dds` 提供的大范围冷暖和明暗变化。
- 更远的政治地图颜色在这套自然地表结果之上混合，具体流程见第六章。

因此，宏观颜色图负责避免整片大陆出现重复纹理感，平铺材质负责避免靠近后只看到低分辨率的大色块。

### 4.5 法线、粗糙度与地形光照

地表光照同时涉及两种尺度的表面方向。

第三章计算的地形法线来自高度图，用于表现山坡、山谷和丘陵的整体朝向。材质法线来自每套地表材质的法线纹理，用于表现石块、土粒和草叶造成的小范围凹凸。材质法线不会改变地形轮廓，只改变光线在表面上的反应。

原版法线纹理采用 RRxG 压缩方式。法线的 X、Y 分量分别保存在纹理的 G、A 通道中，读取后从 0 到 1 还原到 -1 到 1，并根据单位向量关系重建 Z：

```text
x = G × 2 - 1
y = -(A × 2 - 1)
z = sqrt(max(1 - x² - y², 0))
```

Y 需要取反，这是原版法线坐标方向的一部分。把这些纹理交给 Unity 的普通 Normal Map 导入器会触发通道重排，破坏 G、A 中保存的原始数据，因此项目把它们作为线性颜色纹理原样装入数组，并在 Shader 中自行解码。

四层材质法线先使用高度混合后的最终权重合成。高度图法线描述山坡整体朝向，材质法线描述草叶、砂砾和岩石表面的细小凹凸。Unity Shader 负责读取四层法线、完成 RRxG 解码与权重混合；最终光照以高度图法线确定宏观受光方向。

属性纹理的其余三个通道进入地形光照：

| 通道 | 属性 | 画面影响 |
|---|---|---|
| G | 高光强度 | 控制非金属表面的基础反射强弱；读取后乘以 0.25 |
| B | 金属度 | 决定反射颜色来自基础高光还是地表颜色 |
| A | 感知粗糙度 | 决定高光是集中锐利还是宽而柔和 |

感知粗糙度在计算前会平方，转换成光照公式使用的粗糙度。粗糙地面产生宽而弱的高光，湿润或光滑表面产生更集中、更明显的反射。金属度通常对泥土、草地和岩石影响较小，但保留该通道可以支持特殊地表。

最终光照由两部分组成：

- 主方向光根据表面法线、光线方向和阴影衰减计算直接照明。
- 晴天地形环境 Cubemap 提供来自天空和周围环境的间接漫反射与高光反射。

高光部分使用 GGX 微表面模型。它根据粗糙度估算许多微小表面朝向的分布，因此粗糙度变化能够自然地改变高光面积和亮度。方向光、环境反射与阴影计算完成后，政治颜色还可以在光照前后分别混合，使远景色块保持清晰，同时保留部分山体明暗。

### 4.6 地表合成方案的收益与代价

四层材质方案把“材料长什么样”和“材料分布在哪里”分开保存。105 套材质可以在整张世界中反复使用，控制图只需记录编号和权重，不需要为每个地区复制完整的高清颜色、法线和属性纹理。

近景平铺材质与宏观颜色图分工后，可以同时保留两种尺度的质量：靠近时有细密纹理，拉远时有大陆级颜色变化。高度混合又使不同材料按纹理结构相互覆盖，比普通透明插值更接近泥土、岩石和积雪的自然交界。

这套方案的代价主要来自采样数量和数据约束：

- 一个地表像素最多读取四层漫反射、四层法线和四层属性纹理，还要读取控制图与宏观颜色图。
- 三个纹理数组中的所有切片必须保持相同尺寸、格式和 Mipmap 数量。
- 材质编号不能直接使用普通线性过滤，必须手动聚合相邻控制像素中编号相同的权重。
- 世界坐标方向、Y 翻转、平铺偏移或单材质平铺系数错误时，会造成整张地图材质错位。
- 高度混合依赖漫反射 Alpha；如果 Alpha 被当成普通透明度处理，材料边缘会完全错误。
- 完整细节法线参与最终光照后，会增加近景质感，但也会让纹理压缩、法线强度和 Mipmap 选择更加敏感。

与一张覆盖世界的最终彩色贴图相比，这套结构实现更复杂，但能够在完整世界尺度上保留可重复利用的高分辨率地表细节，并允许宏观色调、动态环境材质和政治地图覆盖继续独立变化。

## 5. 省份、行政区划与政治颜色

算法本质：系统先用省份分区图把每个地图位置转换成 Province ID，再通过头衔层级或指定日期的历史领主关系，把 Province ID 映射到对应的政治实体和颜色。Shader 运行时只需查询“地图位置 → Province ID → 当前模式颜色表”，就能在不切割地形网格的情况下生成法理地图或实际领地地图。

政治地图的生成可以概括为一条映射链：

```text
地图坐标
  ↓
Province ID（底层区域编号）
  ↓
男爵领与伯爵领
  ↓
法理王国，或指定日期的实际最高领主
  ↓
政治颜色
```

玩家通常把伯爵领视为地图上的最小完整行政区，但渲染使用的底层单位更细。一个伯爵领可以包含多个男爵领，而每个陆地男爵领通常关联一个 Province ID。普通政治地图会给同一伯爵领内的这些 Province ID 写入相同颜色，因此画面仍表现为完整的伯爵领；更细的编号则可继续服务于地产、占领、选择和局部地图效果。



### 5.1 从地图位置取得 Province ID

`game/map_data/provinces.png` 是世界分区图。它的每种 RGB 颜色代表一个底层区域，但这些颜色只是识别码，并不是国家颜色。`game/map_data/definition.csv` 再把 RGB 识别码转换为整数 Province ID。

地形与省份图使用同一套世界坐标。地图宽 9216、高 4608，因此地表上世界坐标 `(X,Z)` 对应省份图坐标：

```text
U = X / 9216
V = Z / 4608
```

地形 Shader 在绘制每个屏幕像素时，用当前位置的世界坐标查询省份图。这样，政治颜色会直接贴合地表，不需要按照省界切割地形 Mesh。山峰只改变 Y 高度，不改变 XZ 坐标；地形 LOD 改变网格密度，也不会改变省界位置。

省份图使用 Point 过滤并关闭 Mipmap，避免相邻识别色在边界处被平均成不存在的颜色。构建时还会翻转图片上下方向，使图片坐标与 Unity 世界 Z 方向一致。

### 5.2 Province ID、男爵领与伯爵领

`game/common/landed_titles` 把 Province ID 与头衔连接起来。例如一个男爵领可以写有：

```text
b_london = {
    province = 1527
}
```

它表示 Province 1527 属于 `b_london`。上一级伯爵领 `c_middlesex` 可以包含 `b_london`、`b_southwark` 和 `b_woxbrigge` 等多个男爵领，因此一个伯爵领可能覆盖多个 Province ID。

构建政治地图时，程序先找到 Province ID 对应的男爵领，再沿头衔树找到它所属的伯爵领及更高层级。若几个 Province ID 最终属于同一政治实体，颜色表就为它们保存相同颜色。

这种细分不是为了在普通政治地图中显示男爵领边界，而是为了保留更细的游戏空间。原版定义中存在按男爵领计算占领分数的规则，省份覆盖 Shader 也支持第二套颜色，因此同一伯爵领内部仍可表现占领或其他局部状态。

### 5.3 法理归属

法理地图读取 `landed_titles` 中固定的头衔层级：

```text
Province ID → 男爵领 → 伯爵领 → 公国 → 王国 → 帝国
```

例如要生成法理王国地图，程序会为每个 Province ID 沿这条层级向上查找王国头衔，然后把该王国的颜色写入 Province ID 对应的颜色表。最终得到的是“每个 Province ID 应显示哪种法理王国颜色”的静态数据。

法理层级描述制度上的归属，不代表某个历史日期的实际统治关系。

### 5.4 指定日期的实际领地

实际领地还需要读取 `game/history/titles`。历史文件记录头衔在不同日期的持有者和直属领主。项目使用指定日期的有效记录，建立当时的领主链：

```text
Province ID
  → 伯爵领
  → 指定日期的直属领主
  → 继续向上查找
  → 当时的最高 Realm
```

因此两种地图的区别在于：

- 法理地图沿 `landed_titles` 的固定层级向上查找。
- 实际地图沿指定日期的历史领主关系向上查找。

当前生成结果是指定日期的静态快照。若以后加入完整游戏逻辑，实际领地颜色表需要在战争、继承和封臣关系变化后重新生成。

### 5.5 海区、湖泊与不可通行区域

`game/map_data/default.map` 标记海洋、湖泊、大河和不可通行区域。它们必须先分类，再决定是否参与政治着色：

- 海洋、湖泊和大河保留为水域，不直接使用陆地国家颜色。
- 普通陆地按头衔关系取得颜色。
- 不可通行陆地可根据相邻可通行陆地补色，使山脉和荒漠不会在远景政治地图中留下空洞。

补色只统计 `adjacencies.csv` 所描述的有效陆地邻接关系，并采用严格多数：只有某个政治实体在有效邻居中占过半时，才把该颜色赋给不可通行区域。这样可以填补国家内部的无主地带，同时减少边境山脉被随意归给一侧的问题。

### 5.6 传给 Shader 的数据

Unity 不为每个 Province ID 单独创建材质，而是生成一张省份编号纹理和两张颜色表：

- 省份编号纹理：保存每个地图位置的 Province ID。
- 法理颜色表：保存每个 Province ID 的法理颜色。
- 实际颜色表：保存每个 Province ID 在指定日期的实际领地颜色。

Province ID 被拆成两个 8 位通道：

```text
ID = R + G × 256
```

Shader 先从省份编号纹理恢复 ID，再用这个 ID 查询当前地图模式的颜色表。F1/F2 切换只需更换颜色表，不需要修改地形或重新划分行政区。

颜色表的 Alpha 为 0 时，表示该 Province ID 没有政治颜色，Shader 会保留自然地表。这个规则用于水域及尚未归属的区域。

## 6. 政治地图填色与距离场

第五章得到“每个 Province ID 应显示什么颜色”。本章处理的是如何把颜色叠到自然地形上，并形成 CK3 式柔和、连续的政治色边缘。

```text
地图坐标
  → Province ID
  → 当前地图模式的政治颜色
  → 按镜头距离与自然地表混合
  → 在政治边缘附近压暗同色系颜色
```

这里的“边缘渐变”属于地表填色的一部分。第七章的公国、王国边界则是另外绘制的线或边界带，两者不能互相替代。

本算法的本质：输入一张由不同颜色或不同 ID 区域密铺而成的分区图，算法自动找出区域交界，并生成每个位置到最近交界的距离。Shader 再利用这个距离，对每个色块从边界向内部进行渐变、描边、发光、磨损、扩散等处理。

### 6.1 查询政治颜色

最直接的做法确实是：查询一次 Province ID，再取得它的政治颜色。这样可以正确着色，但省界会完全沿着 `provinces.png` 的像素格跳变。斜视地图或缩放画面时，这种逐格跳变容易表现为阶梯状锯齿。

这里需要区分两种数据：

- Province ID 是离散编号，只能取某一个确定值，不能把两个编号混合。
- 政治颜色是普通颜色，可以在边缘处做很窄的平滑过渡。

因此 Shader 不会直接插值 Province ID，而是先读取省份图中包围当前位置的四个相邻像素。每个像素都通过 Point 采样得到一个确定的 Province ID，再分别查询政治颜色：

```text
左下 Province ID → 左下政治颜色
右下 Province ID → 右下政治颜色
左上 Province ID → 左上政治颜色
右上 Province ID → 右上政治颜色
```

这里读取的不是“四个周围省份”，而是“四个相邻的省份图像素”。在国家内部，四个像素通常具有相同 Province ID，四种颜色也完全相同，插值不会改变结果。只有当前位置靠近省界时，四个像素才可能落在边界两侧。

假设边界左侧为红色、右侧为蓝色。当前位置位于两个像素中心之间 25% 的位置时，最终颜色大致为：

```text
最终颜色 = 红色 × 75% + 蓝色 × 25%
```

当位置继续向右移动时，蓝色比例逐渐增加。这只在省界附近形成约一个省份图像素宽的抗锯齿过渡，不会改变任何 Province 的真实归属。政治区域内部仍是原本的纯色。

这个过程称为双线性颜色采样。它解决的是省界在屏幕上的锯齿，不负责生成第 6.3 节所述的宽国境渐变。对应实现位于 `CK3TerrainSurface.shader` 的 `CK3ProvinceColorSample` 和 `CK3BilinearProvinceColorSample`。

### 6.2 与自然地表混合

CK3 的近景需要看清草地、岩石和积雪，远景则需要快速识别国家。因此政治颜色强度会随镜头距离变化：

- 近景：政治色较淡，地表材质和地形明暗占主导。
- 中景：政治色逐渐增强。
- 远景：政治色更稳定，国家范围更容易辨认。

项目为不同镜头高度保存若干组政治色参数，并在相邻高度之间插值，因此缩放时不会突然跳色。

政治色分两次参与地表计算：一部分在光照前与自然材质混合，使山坡和山谷仍有真实明暗；另一部分在光照后补回颜色，防止背光区域过暗而难以辨认。两部分的比例决定政治地图更偏自然地形还是平面地图。

参数插值位于 `Runtime/CK3MapVisualController.cs`，最终混合位于 `Shaders/CK3TerrainSurface.shader`。

### 6.3 用距离场生成颜色内缘

第 6.1 节的颜色插值只消除约一个像素宽的锯齿。CK3 政治地图还有一段更宽的同色系内缘：越靠近国境，政治色越深；进入国家内部后，颜色逐渐恢复正常。

要生成这种效果，Shader 必须知道当前地表位置到国境有多远。项目把这个距离预先保存成灰度纹理：

```text
距离值 d = 0       ：位于政治边缘附近
距离值 d 逐渐增大 ：逐渐进入政治区域内部
距离值 d = 1       ：距离边缘已经足够远
```

这张纹理就是距离场。第 6.4 节说明它如何从政治颜色中生成。

Shader 取得距离 `d` 后，用三个参数控制宽渐变：

```text
E = 深色窄边缘的宽度
G = 宽渐变在窄边缘之外继续延伸的距离
d = 当前像素到政治边缘的距离
```

宽渐变系数为：

```text
渐变系数 = saturate((E + G - d) / G)
```

`saturate` 表示把结果限制在 0 到 1。由此可得：

- 当 `d` 小于 `E` 时，渐变系数为 1，位置非常靠近边界。
- 当 `d` 从 `E` 增加到 `E+G` 时，渐变系数从 1 平滑下降到 0。
- 当 `d` 大于 `E+G` 时，渐变结束，使用区域内部的正常政治色。

窄边缘使用另一条平滑函数：

```text
窄边缘系数 = 1 - smoothstep(E, E + S, d)
```

其中 `S` 是边缘柔和度。`d` 小于 `E` 时窄边缘最强；在 `E` 到 `E+S` 之间逐渐消失。

最终颜色不是统一改成黑色，而是在两种同色系颜色之间混合：

```text
宽渐变颜色 = 本国颜色 × 渐变颜色倍率
窄边缘颜色 = 本国颜色 × 边缘颜色倍率
最终颜色 = 在宽渐变颜色与窄边缘颜色之间按窄边缘系数混合
```

例如红色国家会得到深红色内缘，蓝色国家会得到深蓝色内缘。这样既能强调轮廓，又不会在所有国家之间画出同样生硬的黑边。

距离场比较的是最终政治颜色，而不是 Province ID。两个相邻 Province ID 如果属于同一王国或同一实际 Realm，它们在颜色表中的颜色相同，算法就把它们视为同一区域，不会在内部省界上生成这条渐变。

渐变计算位于 `CK3TerrainSurface.shader` 的 `CK3CalcPrimaryProvinceOverlay`。

### 6.4 距离场怎样生成

政治边界没有预先保存为一组线段。距离场直接从当前地图模式的政治颜色中寻找边界：两个相邻位置的最终政治颜色不同，它们之间就存在政治边界；颜色相同，则不构成边界。

距离场尺寸为 `2304×1152`，长宽都是省份图的四分之一。因此一个距离场像素覆盖省份图中的 `4×4` 像素。生成分为“寻找边界、传播最近边界、输出距离”三个阶段。

#### 第一步：寻找颜色变化

对每个距离场像素，Shader 先查看它在省份图中对应区域的中心颜色，再读取中心周围 `8×8` 范围内的 64 个政治颜色样本。

每个样本都执行下面的判断：

```text
如果样本政治颜色 == 中心政治颜色
    它仍在同一政治区域内

如果样本政治颜色 != 中心政治颜色
    它是一个边界候选点
```

颜色比较使用的是颜色表查询后的 RGBA，而不是 Province ID。例如两个 Province 分别为 100 和 101，但都映射成同一个王国红色，它们会被判定为相同，不产生王国边界。若 Province 101 映射成另一个王国蓝色，则红蓝交界会被判定为边界。

在全部异色样本中，Shader 选择离当前像素中心最近的一个，并保存一条二维向量：

```text
最近边界向量 = 最近异色样本的位置 - 当前像素中心
```

严格来说，真实边界位于两个异色像素之间。这里记录最近异色样本的位置作为边界近似；距离场分辨率、后续线性采样和 Shader 平滑会共同消除这半个像素量级的误差。

靠近国境的像素通常能在 `8×8` 范围内找到异色样本。国家内部的像素暂时找不到，需要下一阶段取得远处边界的位置。

#### 第二步：传播最近边界

已经找到边界的像素保存“自己到最近边界的向量”。周围像素可以复用这个结果。

假设像素 B 知道最近边界位于它右侧 20 个单位处，像素 A 位于 B 左侧 4 个单位。那么对 A 来说，同一个边界位于右侧 24 个单位处：

```text
A 到边界的向量 = A 到 B 的偏移 + B 到边界的向量
```

每轮传播时，每个像素读取周围八个方向的邻居，将邻居保存的向量换算成“从自己出发”的向量，然后保留长度最短的一条。

传播步长依次为：

```text
16 → 8 → 4 → 2 → 1
```

较大的步长先把边界信息快速传入政治区域内部，较小的步长再修正最近边界的位置。这里的步长以距离场像素计算；因为距离场缩小了四倍，步长 16 相当于省份图上的 64 个像素。

这种方法不需要让每个像素扫描整张世界图，也不需要从边界开始逐像素扩散数百轮。所有距离场像素可以在同一轮 GPU Pass 中并行比较邻居。

#### 第三步：把向量转换成灰度距离

传播结束后，每个像素都保存一条指向最近边界的二维向量。Shader 计算向量长度，并除以最大搜索距离 127：

```text
距离值 = length(最近边界向量) / 127
```

结果被写入单通道灰度纹理：

- 靠近边界时向量很短，灰度接近 0。
- 越深入政治区域，向量越长，灰度越接近 1。
- 超过搜索范围后统一按区域内部处理。

运行时地表 Shader 读取这个灰度值，再按照第 6.3 节的 `E`、`G` 和 `S` 参数生成宽渐变与窄边缘。

法理地图和实际领地地图必须分别生成距离场，因为同一 Province 在两种模式中可能属于不同政治实体，两种地图的颜色交界也就不同。

构建流程位于 `Editor/CK3ProvinceDistanceFieldBuilder.cs`。边界检测、八方向传播和最终距离换算分别位于 `Shaders/CK3ProvinceDistanceField.shader` 的 `Init`、`Fill` 和 `Finalize` Pass。

### 6.5 水域对政治边缘的影响

海岸线在近景中应该清楚，但远景中不应把跨海国家强行切成多个互不相连的色块。为此项目生成两种距离场：

- 保留水岸的距离场：海岸和湖岸也会形成边缘。
- 忽略普通水域的距离场：计算国家整体轮廓时，水域可以作为“通配区域”参与传播。

镜头较近时主要使用第一种，强调海岸；镜头拉远时逐渐使用第二种，使跨海领地保持更完整的政治轮廓。

忽略水域并不等于把海洋染成国家颜色。它只影响“最近政治边缘在哪里”的计算，水面仍由水体 Shader 绘制。若水域两侧属于不同政治实体，算法仍会保留真正的政治分界，避免把敌对国家跨海合并。

水域通配颜色表由 `Editor/CK3ProvinceDistanceFieldBuilder.cs` 生成，镜头高度切换位于 `Runtime/CK3MapVisualController.cs`。

### 6.6 方案特点

省份编号、政治颜色和边缘距离分开保存，因此三者可以独立更新：

- 改变国家颜色，只需更新颜色表。
- 切换法理与实际地图，只需切换颜色表和对应距离场。
- 地形 LOD 改变时，政治边界仍由同一世界坐标查询，不会漂移。
- 距离场让边缘宽度和柔和程度可以独立调节。

代价是政治关系变化后需要重新生成相应距离场；四分之一分辨率也会损失极细小区域的距离精度。省份本身的归属仍由完整分辨率编号纹理决定，因此这种误差主要影响渐变宽度，不会改变 Province ID。

| 生成普通与水域通配距离场 | `Editor/CK3ProvinceDistanceFieldBuilder.cs` |

## 7. 多层级地图边界

**本章本质：先从相邻行政区域中提取连续边界路径，再把路径扩展成具有宽度的带状 Mesh，最后用不同笔刷和缩放规则绘制省界、公国界、领地边界与交互轮廓。**

第六章的距离场只负责在政治色块内部形成柔和的深色渐变。公国边界、领地边界、选中轮廓和战争边界则需要清晰的线条、不同的笔触以及独立的显隐规则，所以 CK3 使用另一套几何边界系统。

这里的“几何边界”可以理解为铺在地表上的狭长 Mesh。它像一条很窄的丝带：丝带的中心沿着行政区边缘延伸，左右宽度决定边界线有多粗，表面再贴上原版的边界笔刷纹理。

这套系统的基本流程是：

```text
省份与政治关系
  → 判断相邻区域之间属于哪一种边界
  → 把相邻的边界像素整理成连续路径
  → 为路径生成带宽度的几何
  → 使用对应的边界笔刷绘制
```

边界 Shader 不负责寻找省界。地图数据处理阶段先生成这条“丝带”的顶点；Shader 接收已经生成好的位置和纹理坐标，只负责把它画到地图上。

### 7.1 为什么使用独立边界几何

直接在地表 Shader 中比较相邻 Province ID，也能得到一条最基本的省界，但这种结果只回答“这里是否存在边界”。它无法决定这条线应当使用什么笔触、显示多粗以及在哪个缩放档位消失，因此不能完整表达 CK3 的边界系统：

- 不同边界需要不同宽度和笔触。
- 省份、伯爵领、直属领地、其他 Realm 和不可通行区域具有不同可见缩放区间。
- 选中、悬停、战争和外交状态需要临时增加或替换边界样式。
- 边界纹理需要沿路径连续重复，而不是在每个地表像素中重新开始。
- 边界需要独立设置透明混合、深度偏移和模板测试。

因此政治填色与几何边界分成两个系统：

```text
政治填色：地表 Shader 根据 Province ID 查询颜色
几何边界：CPU 生成连续边界路径，Border Shader 绘制纹理带
```

前者适合覆盖大面积区域，后者适合绘制具有明确宽度和笔触的线状内容。

### 7.2 边界类型与缩放区间

`game/gfx/map/borders/settings.txt` 定义了边界类型使用的纹理、Shader Effect 和可见缩放范围。文件左侧的类型名称由原版程序预先定义，并不是任意命名的材质槽。

基础类型包括：

| 类型 | 含义 | 原版缩放区间 |
|---|---|---:|
| `water` | 水域相关边界 | 0–7 |
| `province` | Province 底层边界 | 0–10 |
| `county` | 伯爵领边界 | 0–15 |
| `domain` | 直属领地边界 | 0–20 |
| `other_realm` | 其他 Realm 的边界 | 0–15 |
| `sub_realm` | Realm 内部下级领地边界 | 0–9 |
| `impassable` | 不可通行区域边界 | 0–20 |

这里的数字是原版地图缩放档位。当前档位不在配置区间内时，对应边界类型不参与绘制。不同类型使用不同区间，因此镜头缩放时，细小省界可以先隐藏，而更重要的领地轮廓继续保留。

原版边界不能简单概括为“公国细线、王国粗线”。实际类型还取决于玩家与该区域的关系。例如同一条地理分界在不同状态下可能使用 `my_realm`、`other_realm`、`sub_realm`、`selected_realm` 或战争边界。头衔等级只提供判断边界类型所需的一部分政治数据。

选中和交互状态还定义了：

- `highlighted_province`
- `selected_province`
- `hovered_realm`
- `selected_realm`
- `selected_realm_overlord`
- 外交、战争、斗争和灾害等专用类型

每种类型可以指定自己的 DDS 纹理，也可以覆盖默认 Effect。这样无需修改边界几何，就能改变选中、战争或外交状态的视觉样式。

### 7.3 从区域关系到连续边界

省份图只保存每个地图像素属于哪个 Province，不直接保存一条条连续线。生成几何边界时，地图数据处理阶段需要先完成两项工作：

1. 比较相邻区域，判断它们之间是否需要边界以及使用哪种边界类型。
2. 把离散的边界位置连接成连续路径，供后续生成几何。

原版二进制已经确认存在以下独立阶段：

```text
GenerateBorders
  → ExtractSegments
  → AddStaticBorders / UpdateBorders
  → SyncBorders
```

`GenerateBorders` 和 `ExtractSegments` 说明边界提取发生在绘制之前，而不是 `pdxborder.shader` 中。原版还保留错误信息：

```text
Border search failed to find next border pixel (corrupt province image?)
```

这说明提取器会沿省份图中的边界位置寻找下一个可连接点，并期望最终得到连续线段。生成结果由 `CBorderManager` 管理；静态边界、更新后的政治边界和临时交互边界可以分别加入、同步或移除。

### 7.4 边界带 Mesh 与 UV

`pdxborder.shader` 接收两类顶点数据：

```text
Position：这个顶点放在地图的什么位置
UV：这个顶点对应边界笔刷图片中的什么位置
```

这说明前面的生成阶段输出的不是一条没有宽度的数学线，而是一条已经具有宽度、可以直接绘制的丝带。边界宽度、转角连接和纹理方向必须先转换成顶点与三角形。

边界纹理的采样方式为：

```text
U 方向：Wrap
V 方向：Clamp
```

它表明边界笔刷会沿着整条路径重复，而从边界左侧到右侧只读取一次笔刷横截面。可以把它想成用滚轮刷沿着一条曲线滚动：一个 UV 方向记录滚轮已经向前走了多远，另一个 UV 方向记录当前位置位于丝带左边、中心还是右边。

边界 DDS 不只是颜色贴图。它的 RGB 和 Alpha 共同决定笔触的颜色变化、横向形状、透明区域和柔和边缘。因此把它替换成纯色线，会丢失原版边界的纸面笔触和层次感。

### 7.5 贴合地形与 Flat Map 过渡

边界顶点进入 Shader 时已经包含三维 `Position`。也就是说，边界在地图上的水平位置和贴地高度已经由前面的生成阶段决定。顶点 Shader 只处理从立体地形向平面地图过渡：

```text
position = 输入的边界顶点位置
position.y = lerp(position.y, FlatMapHeight, FlatMapLerp)
position.y += HeightOffset
```

`lerp` 表示在两个高度之间平滑过渡。在立体地形模式下，`FlatMapLerp` 接近 0，边界保留输入的地形高度；切换到平面地图时，这个数逐渐接近 1，边界高度也逐渐变成统一的 `FlatMapHeight`。因此边界会与地形一起压平，不会悬浮在原来的山体高度。

`HeightOffset` 会把边界轻微抬高。这样边界和地表不会争夺同一个深度位置，镜头移动时也不容易出现两者交替显示的闪烁。原版还设置了额外的显卡深度偏移：

```text
DepthBias = -30000
SlopeScaleDepthBias = -2
```

这两种偏移的目的相同：视觉上仍让边界贴着地面，但在深度判断时让它稳定地显示在地表上方。

当 Flat Map 开始出现时，像素 Shader 还会读取 `surround_mask.dds`，裁掉桌面地图纸张范围之外的边界。这样边界不会延伸到 Surround Map 或桌面装饰区域。

### 7.6 Border Shader 的绘制过程

普通边界的像素绘制顺序如下：

```text
使用 UV 读取当前类型的 BorderTexture
  → 纹理 RGB 得到笔触颜色
  → 纹理 Alpha 得到边界透明度
  → 乘以边界对象的整体 Alpha
  → 应用战争迷雾、阴影、云影和远景雾
  → 使用 Alpha Blend 合成到已有地图画面
```

边界纹理使用线性过滤和 Mipmap，沿 U 方向重复、沿 V 方向 Clamp。线性过滤使笔刷横截面保持柔和，Mipmap 减少远处观察细线时的闪烁。

普通边界使用标准 Alpha Blend：

```text
输出颜色 = 边界颜色 × 边界 Alpha
         + 背景颜色 × (1 - 边界 Alpha)
```

深度测试开启，表示山体或其他真正位于前方的物体仍然可以遮住边界。边界本身不写入深度，因此不会挡住之后绘制的其他透明地图元素。

模板测试可以理解为一张“这里允许不允许画边界”的遮罩。原版规则为：

```text
StencilFunc = not_equal
StencilRef = 1
```

只有遮罩值不等于 1 的位置才绘制边界。这样其他地图阶段可以先把某些区域标记为不可绘制，边界经过这些区域时就会被裁掉。

战争、斗争等边界可以选择不同 Pixel Shader。战争边界会随时间改变纹理亮度和 Alpha，形成沿路径移动或脉冲的视觉效果；它仍然复用同一套边界几何和 UV。

### 7.7 方案特点与源码入口

独立边界几何的主要收益是：

- 边界笔刷、宽度、透明度和缩放范围可以按类型分别控制。
- 政治填色变化不要求修改地形 Mesh。
- 选中、悬停和战争状态可以复用已有路径并替换样式。
- 深度、模板、雾和 Flat Map 过渡可以独立于地表材质处理。

代价是程序必须维护“哪些线段相连、在哪里转弯、在哪里分叉”这套连接关系。政治关系发生变化时，受影响的边界路径和类型也需要更新；连接错误会表现为断线或黑点，纹理坐标错误则会表现为笔刷突然跳变。

原版技术入口如下：

| 内容 | 原版入口 |
|---|---|
| 边界类型、DDS、Effect 和缩放范围 | `game/gfx/map/borders/settings.txt` |
| 普通、战争和斗争边界 Shader | `game/gfx/FX/pdxborder.shader` |
| 顶点输入与边界常量 | `jomini/gfx/FX/jomini/jomini_flat_border.fxh` |
| 边界笔刷纹理 | `game/gfx/map/borders/*.dds` |
| CPU 生成与管理阶段 | `jomini_border_generation.cpp`、`border_segment_extractor.cpp`、`jomini_border_manager.cpp`、`jomini_border_interface.cpp` |

## 8. 海洋、湖泊与海岸

**本章本质：在整个世界上铺一张固定高度的水面，再比较水面与地形的高度，只有地形低于水面的地方才真正显示海水。**

### 8.1 一张覆盖完整世界的海面

CK3 的基础海平面高度为 3，世界范围为 X 方向 `0–9215`、Z 方向 `0–4607`。普通海洋只使用四个顶点：

```text
(0, 3, 0)             (0, 3, 4607)
(9215, 3, 0)          (9215, 3, 4607)
```

四个顶点连接成两个三角形，形成一张覆盖完整地图的水平面。它不需要按照海岸线切割，也不需要为每个海区创建独立 Mesh。

这张水面实际上也位于陆地下面或内部。陆地为什么不会全部被水覆盖，由下一步的水深判断决定。

### 8.2 用地形高度决定哪里显示水

水面 Shader 在每个位置读取地形高度，并计算：

```text
水深 = 海平面高度 - 地形高度
```

结果有三种情况：

- 地形高于海平面：水深小于 0，水面完全透明。
- 地形刚低于海平面：水面逐渐出现，形成柔和海岸。
- 地形明显低于海平面：水面完全显示。

因此真正决定海岸轮廓的是高度图，而不是海区政治颜色。海面虽然是一整张矩形，但只有低洼区域能够被看见。

岸边透明度由两个参数控制：

- `WaterFadeShoreMaskDepth`：从多深的位置开始完全显示水。
- `WaterFadeShoreMaskSharpness`：透明变化有多快。

Shader 对地形高度取中心和周围八个样本的平均值，避免海岸透明度严格沿单个高度像素跳变。

### 8.3 水色与平面地图过渡

`watercolor_rgb_waterspec_a.dds` 覆盖完整世界。它的 RGB 保存不同海域的基础水色，Alpha 保存水面高光输入。水面 Shader 用世界 XZ 坐标查询这张纹理，因此地中海、北海和印度洋可以具有不同色调，而不是共用一种蓝色。

地图进入 Flat Map 时，地形会压到统一高度。水面也必须同步抬升，否则会被压平后的地形盖住。Unity 中使用：

```text
立体地图水面高度 = 3
平面地图显示高度 = FlatMapHeight + 0.02
```

二者随 `FlatMapLerp` 平滑过渡。`0.02` 只用于解决 Unity 的共面深度闪烁；计算真实水深时仍使用原版海平面 3。

### 8.4 湖泊与源码入口

`default.map` 单独列出海区和湖泊。海拔低于 3 的湖泊可以由基础海面自然显示；高于基础海平面的湖泊需要独立的水面高度和几何。原版 Shader 为这类水体提供 `lake` 与 `lake_mapobject` Effect，使湖泊可以沿用水体的颜色、高光和透明度处理，同时不受全局海平面高度限制。

| 内容 | 源码入口 |
|---|---|
| 构建四角世界海面、水色纹理和材质 | `Editor/CK3WaterSurfaceBuilder.cs` |
| 保存海平面、岸边淡出和 Unity 平面补偿参数 | `Runtime/CK3WaterSurfaceBinding.cs` |
| 查询地形高度并计算水面透明度 | `Shaders/CK3WaterSurface.shader` |
| 原版水体配置 | `game/gfx/map/water/water.settings` |
| 原版完整水体 Shader | `game/gfx/FX/pdxwater.shader` |

## 9. 河流系统

**本章本质：把 `rivers.png` 中一个个河流像素连接成河道中心线，再沿中心线向左右扩展，生成具有宽度的河面。**

### 9.1 `rivers.png` 不是一张河流贴图

`game/map_data/rivers.png` 与地图使用相同坐标。它不是直接贴到地形上的可见图片，而是一张索引色数据图：

- 白色表示普通陆地背景。
- 洋红色表示海洋背景。
- 蓝色和青色系列表示不同宽度的河流路径。
- 红色和绿色标记河流源点或支流连接点，本身不是可见河水。

调色板索引具有明确用途：

```text
0       主河源点
1、2    需要连接到已有河流的次级源点
3–253   可以组成河流中心线的路径像素
254、255 水域与陆地背景
```

这一步最重要的是先区分“控制标记”和“可见河道”。如果把洋红海洋背景或红绿源点直接当成河流绘制，就会出现海里全是河流或所有河流同宽的问题。

### 9.2 从像素连接成连续河网

构建器先扫描整张图，记录所有主河源点和次级源点，然后按原版顺序生成河流。

主河从索引 0 开始。每到一个河流像素，只检查四个方向：

```text
左 → 右 → 上 → 下
```

程序选择第一个尚未访问、索引位于 `3–253` 的相邻像素，继续向前追踪。直到找不到下一个有效像素，一条主河中心线完成。

次级源点 1 和 2 表示支流或后续河段。它们不能独立开始，必须先在四邻域中找到已经属于某条河流的像素。找到后，次级河流记录这条父河，并从连接点继续追踪自己的路径。

所有主河先生成，次级河流再分批连接。若某个次级源找不到父河，该标记不会生成河段。这样可以避免在缺少连接关系时产生穿过陆地的错误河流。

最终保存的数据包括：

- 每条河流在点数组中的起点和点数。
- 它属于主河还是次级河流。
- 它连接到哪条父河。
- 每个路径点的地图坐标和宽度。

### 9.3 宽度、平滑与河面 Mesh

河流宽度由路径像素的索引决定。CK3 定义了 13 级宽度，范围从 1 到 4；源点使用很小的固定宽度 0.01，使河道能从源头逐渐展开。宽度沿中心线保存，而不是为所有河流使用同一个数值。

直接连接位图像素会形成明显直角，所以路径还要经过两步处理：

1. 对位置和宽度做两轮邻点平均，减弱像素网格造成的折角。
2. 使用 Catmull-Rom 曲线连接控制点；弯曲较大的位置增加更多采样点，较直的河段保留较少采样点。

平滑后的每个中心点都有位置、前进方向和宽度。程序计算一条与前进方向垂直的向量，并向左右各移动半个河宽：

```text
左岸点 = 中心点 - 垂直方向 × 河宽 / 2
右岸点 = 中心点 + 垂直方向 × 河宽 / 2
```

相邻的左右岸点连接成两个三角形，整条河最终成为一条连续的带状 Mesh。UV 中的 U 沿河流累计距离，V 从左岸的 0 变化到右岸的 1，使水面纹理能够顺着河道延伸。

### 9.4 贴合地形、河面显示与源码入口

河面 Mesh 只保存 XZ 位置，顶点 Shader 使用与 Terrain 相同的高度页表查询该位置的地形高度：

```text
河面高度 = 地形高度 + RiverHeightOffset
```

这样河流会贴着山谷和坡地起伏。`RiverHeightOffset` 只把河面轻微抬高，避免它与地形处在完全相同的深度而闪烁。进入 Flat Map 时，河面高度与地形一起过渡到统一平面高度。

河面 Shader 使用完整世界水色图取得当地水色，并让河道左右两岸的 Alpha 平滑降为 0，从而隐藏带状 Mesh 的硬边。不同宽度的河面共用同一套材质，宽度变化已经编码在 Mesh 顶点的位置中。

| 内容 | 源码入口 |
|---|---|
| 解析索引色、追踪主河和支流 | `Editor/CK3RiverNetworkBuilder.cs` |
| 保存河流、父河、路径点和宽度 | `Runtime/CK3RiverNetworkData.cs` |
| 平滑曲线并生成带状河面 Mesh | `Editor/CK3RiverSurfaceBuilder.cs` |
| 贴合高度、读取水色并处理岸边透明度 | `Shaders/CK3RiverSurface.shader` |
| 暴露河面高度、颜色和透明度 | `Runtime/CK3RiverSurfaceBinding.cs` |
| 原版河面与河底 Shader | `game/gfx/FX/river_surface.shader`、`game/gfx/FX/river_bottom.shader` |

## 10. 曲线地图名称

**本章本质：把属于同一政治实体的地图区域合并成 Area，在 Area 内寻找一条适合放字的长线，再把每个字形沿曲线逐个排布并贴合地形。**

### 10.1 从政治实体得到名称区域

地图名称不是一个放在包围盒中心的 TextMesh。系统先根据地图模式，把 Province 分组为需要显示名称的 Area：

- 法理王国地图按法理王国分组。
- 实际领地地图按指定日期的 Realm 分组。
- 同一政治实体中彼此不相连的领土分别处理，避免一个名称跨越相距很远的飞地。

每个 Area 保存名称文本、包含的 Province 集合和地图像素范围。名称文本来自原版本地化与主头衔数据，区域形状则来自省份图。

### 10.2 在不规则区域中寻找排字方向

Area 往往不是规则矩形。程序对区域内部像素做间隔采样，统计中心位置以及 X、Y 的变化关系，再得到两条可能的主方向：

- 以 X 为主的方向，适合横向或斜向展开的区域。
- 以 Y 为主的方向，适合南北狭长的区域。

每个方向都以区域中心为基准，测试从 `-5` 到 `+5` 的十一条平行线。测试线与 Area 相交后可能被孔洞或海峡切成多段，程序优先选择穿过区域中心的连续段；没有穿过中心时，选择离中心最近的段。

两个方向各自得到一条候选长线。横向候选的长度比较会乘以 `HORIZONTAL_BIAS = 1.6`，因此大多数国家名称倾向横排，狭长区域仍可以选择竖排或大角度斜排。

### 10.3 跨海区域怎样保持合理连通

区域面积、中心和字号只统计该政治实体自己的陆地 Province。海区、湖泊和大河不会增加领土面积，也不会把名称中心拉进水中。

在寻找候选线时，允许指定水域充当“可穿过但不计面积”的连接区域。这样横跨爱琴海的领地可以得到一条连续候选线，而不是被水域强制切成欧洲与安纳托利亚两段。水域只影响排字线路的连通性，不改变政治归属。

### 10.4 字号与字符间距

字号同时受到横向空间和纵向空间限制：

```text
横向适配 = 候选线长度 / 文字原始宽度
纵向适配 = Area 平均可用厚度 / 文字原始高度
```

Area 的平均可用厚度由区域面积除以候选线长度得到。宽阔区域主要受横向长度限制，狭长区域主要受纵向厚度限制。接近方形的区域会使用专门的宽高判断，避免短名称被无条件放大。

文字排版保留字体自身的字形宽度和 advance。区域比文字更长时，只在字符之间增加间距，并由 `MAX_STRETCH_FACTOR` 限制拉伸量；不会把每个字符强行缩放成相同宽度。

### 10.5 从直线生成曲线文字

选定候选线后，程序沿文字首部、中部和尾部重新测量 Area 的横截面，得到五个控制点：

```text
外推起点 → 首部截面中心 → 中部平均点 → 尾部截面中心 → 外推终点
```

五点构成前后两段 Catmull-Rom 曲线。每个字形先按字体度量生成普通四边形，再根据它在整行文字中的水平位置取得曲线参数。曲线同时返回位置和切线：

- 位置决定字形中心放在哪里。
- 切线决定字形朝向。
- 与切线垂直的方向决定字形上下两侧。

因此整行文字可以平滑弯曲，每个字符又保持连续方向，不需要把一个平面文本对象整体旋转。

### 10.6 地形贴合与文字 Shader

字形 Mesh 保存世界 XZ、字体 Atlas UV 和颜色所需数据。顶点 Shader 使用与 Terrain 相同的高度页表查询 XZ 对应的 Y，使文字贴在可见地形表面。进入 Flat Map 时，名称与地形共同向 `FlatMapHeight` 过渡，因此镜头平移不会产生文字与底图之间的视差。

字体 Atlas 使用单通道有符号距离场。像素 Shader 根据距离值生成字形内部和描边，再叠加 `rough_texture_overlay.dds`，让文字边缘保留纸面式的不均匀感。名称使用 Alpha Blend、不写深度，并通过模板遮罩限制绘制区域。

| 内容 | 源码入口 |
|---|---|
| 生成法理与实际领地名称源 | `Editor/CK3MapNameSourceBuilder.cs` |
| Area 分析、候选线、字号和曲线 Mesh | `Editor/CK3MapNameMeshBuilder.cs` |
| 名称源数据结构 | `Runtime/CK3MapNameSourceData.cs` |
| 高度贴合、SDF 字体和描边 | `Shaders/CK3MapName.shader` |
| 原版字体与名称渲染 | `game/fonts/fonts.font`、`jomini/gfx/FX/jomini/countrynames.fxh`、`game/gfx/FX/mapname.shader` |

## 11. 树木、城市与城堡

**本章本质：模型文件决定“画什么”，实例数据决定“画在哪里”，渲染器把使用同一模型和材质的大量实例分批提交给 GPU。**

### 11.1 模型、材质和实例位置

近景装饰由三类数据共同组成：

| 数据 | 作用 |
|---|---|
| `.mesh` | 保存顶点、法线、切线、UV、三角形和子网格 |
| `.asset` | 为子网格指定 diffuse、normal、properties、tint 等纹理与 Shader |
| `map_object_data` | 保存每个实例的位置、旋转、缩放和所用模型 |

树木实例来自 `game/gfx/map/map_object_data/generated/tree*generator*.txt`。每条实例记录包含 10 个浮点数：三维位置、四元数旋转和三维缩放。

城堡等领地建筑还会结合 `building_locators.txt` 与省份历史中的 holding 类型。Locator 给出某个 Province 的建筑位置，holding 数据决定这个位置应显示城堡、城市还是神殿类别。

### 11.2 PDX Mesh 转换

Editor 构建器读取 PDX 二进制 Mesh 中的：

```text
p   顶点位置
n   顶点法线
ta  顶点切线
u0  第一套纹理坐标
tri 三角形索引
```

这些数据分别写入 Unity Mesh 对应通道。一个原版模型包含多个材质部分时，每部分保存为独立子网格，并按照相邻 `.asset` 中的材质设置绑定纹理。模型的几何与材质关系由此保持一致，不需要重新手工拆模。

原版坐标经过轴向转换后写成 Unity 的 `Matrix4x4.TRS`。位置、Quaternion 和 Scale 共同决定一个实例在世界中的完整变换。

### 11.3 贴合地形

树木与建筑的 XZ 来自原版实例数据。构建阶段使用与 Terrain 相同的高度页表查询该位置的地面 Y，再把实例放到地表。

这一步只修正实例的落地高度，不改变原版 XZ、旋转和缩放。地形与装饰物查询同一份高度数据，因此山坡上的树木、城堡和城市能够随地形一起起伏。

### 11.4 分块实例化绘制

数十万棵树不适合各自创建 GameObject。系统先按模型和材质组成批次，再按 256 个世界单位划分空间块。每个空间块保存一组实例矩阵。

绘制时只提交相机视野和可见距离内的空间块。同一批次使用 `Graphics.DrawMeshInstanced` 绘制，单次调用可以提交多份变换矩阵：

```text
一份 Mesh + 一份 Material + 多个实例矩阵
```

这样既保留原版完整实例位置，又避免为每棵树维护独立组件和 Renderer。

### 11.5 缩放淡出

`layers.txt` 为树木和建筑定义 `fade_out = 9`。接近该缩放档位时，装饰物不是整批突然消失，而是逐渐降低实例透明度。

树木和建筑属于不透明或 Alpha Cutout 物体，直接降低普通 Alpha 会产生排序问题。因此 Shader 使用屏幕空间抖动：透明度越低，被丢弃的像素越多；经过抗锯齿后表现为平滑淡出。

### 11.6 树木与建筑材质

树叶材质双面绘制，并以 Alpha Cutoff `0.4` 裁掉纹理透明区域。树木颜色由 diffuse、tint 和 normal 纹理共同决定；Tint Map 为不同实例提供颜色变化，避免整片森林呈现完全相同的色调。

城堡、城市和神殿使用 diffuse、normal 与 properties 图。Diffuse 提供颜色，Normal 提供砖石细节，Properties 提供粗糙度和高光等表面属性。它们使用实体表面材质并写入深度，可以正确遮挡地形后的其他装饰。

| 内容 | 源码入口 |
|---|---|
| PDX Mesh、材质和实例数据导入 | `Editor/CK3DecorationBuilder.cs` |
| 批次、空间分块和实例绘制 | `Runtime/CK3DecorationRenderer.cs` |
| 树叶颜色、裁切与淡出 | `Shaders/CK3TreeSurface.shader` |
| 建筑表面与淡出 | `Shaders/CK3DecorationSurface.shader` |
| 原版树木与建筑输入 | `game/gfx/models/mapitems/trees`、`game/gfx/models/buildings/holdings`、`game/gfx/map/map_object_data` |

## 12. 桌面、手绘地图与世界外侧

**本章本质：最远景不是把地图换成一张背景图，而是让地形和水面共同变成手绘纸图，同时在地图矩形外显示独立的桌面与 Surround Map。**

### 12.1 桌面模型

默认西式桌面由四个独立对象组成：

- 桌体。
- 蜡烛。
- 桌布。
- 剑、杯、书、硬币和书写工具等道具。

`map_table_western.txt` 保存它们的实体引用和 Transform。四组 PDX Mesh 保留完整子网格，场景对象直接采用原始位置与缩放。桌面位于地图下方，负责构成世界地图周围可见的实体环境。

### 12.2 Flat Map 手绘图

`flatmap.dds` 是覆盖完整世界的手绘地图，尺寸为 `9216×4608`。它不作为地形下面的一张 Quad，而是进入 Terrain 和 Water Shader：

```text
立体地形颜色 ─┐
              ├─ 按 FlatMapLerp 混合 → 手绘纸图
立体水面颜色 ─┘
```

与此同时，地形顶点向统一的 `FlatMapHeight` 压平。这样颜色与几何同步变化：山峰逐渐变平，自然地表和海水逐渐变成同一张手绘地图，而不会出现仍然起伏的纸图。

### 12.3 撕纸式过渡

从立体地图切到 Flat Map 时，不使用覆盖全屏的均匀淡入。`paper_tear_mask.dds` 会以三种 UV 尺度采样，再通过阈值与 `smoothstep` 生成不规则过渡边缘。

结果类似一层手绘纸张从不同位置逐渐覆盖立体地图。Terrain 与 Water 使用同一份遮罩和同一个 `FlatMapLerp`，因此海岸两侧的过渡能够保持同步。

### 12.4 Surround Map 与世界外侧

完整世界数据只覆盖 `9216×4608` 的地图矩形，镜头拉远后仍会看到矩形之外的区域。Surround Map 使用独立表面、`surround_mask.dds` 和 `surround_fade.dds` 处理这部分画面。

Surround Map 与 Flat Map 的职责不同：

- Flat Map 替换世界矩形内部的地形与水面颜色。
- Surround Map 填充世界矩形外侧，并控制边缘、云层和阴影的淡出。
- Tabletop 是更下方的三维桌体和装饰。

三层组合后，地图纸张、世界外侧画面与桌面模型能够在远景中连续衔接。

| 内容 | 源码入口 |
|---|---|
| 桌面 Mesh、材质、Transform 和场景绑定 | `Editor/CK3TabletopFlatMapBuilder.cs` |
| 桌面表面材质 | `Shaders/CK3TabletopSurface.shader` |
| 世界外侧遮罩与淡出 | `Shaders/CK3SurroundMap.shader` |
| 桌面缩放可见性 | `Runtime/CK3TabletopVisibility.cs` |
| 原版桌面与远景输入 | `game/gfx/map/map_object_data/map_table_western.txt`、`game/gfx/models/tabletop`、`game/gfx/map/terrain/flat_maps`、`game/gfx/map/surround_map` |

## 13. 光照与最终画面合成

**本章本质：地表材质先生成颜色和表面属性，再经过太阳光与环境光计算明暗；政治颜色在光照前后分两次混合，最后由 URP 对整幅画面执行后处理。**

### 13.1 地形光照

第四章得到的四层地表材质会输出：

- 漫反射颜色。
- 地形与材质法线。
- 粗糙度。
- 金属度。
- 高光强度。

方向光根据太阳方向、表面法线和阴影决定直接受光。高光使用 GGX 分布，粗糙表面得到宽而弱的高光，光滑表面得到窄而亮的高光。晴天地形环境 Cubemap 提供间接光，使背光坡面仍保留环境颜色，而不是完全变黑。

### 13.2 政治颜色为什么分两次混合

政治颜色如果全部在光照之后覆盖，会遮掉山脉和谷地的明暗；如果全部在光照之前混合，远景色块又可能被强光和材质颜色削弱。

地形 Shader 因此把政治颜色分为两次：

```text
自然地表颜色
  → 混入 Pre-Lighting 政治色
  → 计算太阳光、阴影、环境光和高光
  → 混入 Post-Lighting 政治色
```

Pre-Lighting 部分保留地形受光，Post-Lighting 部分恢复地图模式的颜色识别度。边缘距离场产生的同色深边也沿用同一混合链。

### 13.3 不同地图元素如何受光

- Terrain 使用完整地表材质属性、方向光、阴影和环境光。
- 树木与建筑使用自身法线和材质纹理接受场景方向光。
- 水面与河流以透明层覆盖地表，使用水色、透明度和表面效果参与合成。
- 地图名称与行政边界属于信息层，主要保持笔触颜色和可读性，不按普通实体物体方式重新着色。
- Flat Map 接近完全显示时，手绘颜色逐渐取代自然地表的材质光照结果。

### 13.4 镜头高度与后处理

镜头高度控制的是地图层之间的权重，而不是重新生成地图：

- 近景突出地形材质、树木和建筑。
- 中远景提高政治填色、边界和地图名称的可见性。
- 第 20 到 21 缩放档驱动地形压平、手绘图和桌面环境出现。

所有地图层完成合成后，URP Volume 对相机输出执行曝光、色彩调整、Tonemapping、Bloom 和抗锯齿。后处理作用于完整画面，不写入各地图 Shader，因此可以直接使用 Unity 自带组件调整整体风格。

| 内容 | 源码入口 |
|---|---|
| 地表材质、GGX、环境光和政治色双阶段混合 | `Shaders/CK3TerrainSurface.shader` |
| 光照参数与材质库绑定 | `Runtime/CK3TerrainSurfaceBinding.cs` |
| 镜头缩放和层级权重 | `Runtime/CK3StrategicMapCamera.cs`、`Runtime/CK3MapModeController.cs` |
| 原版地图光照 | `game/gfx/FX/jomini/map_lighting.fxh`、`game/gfx/FX/cw/lighting.fxh` |
| 后处理 | Unity URP Volume |

## 14. Shader 实现总览

**本章本质：前面各章生成的数据最终分别进入多个 Shader；每个 Shader 只处理一种地图层，并通过明确的深度、混合和绘制顺序组合成完整画面。**

### 14.1 各 Shader 的职责

| Shader | 主要输入 | 输出 |
|---|---|---|
| `CK3TerrainSurface.shader` | 高度页表、四层地表材质、宏观颜色、省份颜色、距离场、Flat Map | 不透明地形、政治填色和手绘地图 |
| `CK3ProvinceDistanceField.shader` | 当前地图模式的政治颜色 | 到最近政治边缘的距离纹理 |
| `pdxborder.shader` | 边界带 Mesh、UV、边界笔刷和类型参数 | 省界、公国界、领地边界及状态边界 |
| `CK3WaterSurface.shader` | 海平面、地形高度、水色、Flat Map、撕纸遮罩 | 海洋与海岸透明层 |
| `CK3RiverSurface.shader` | 河面带状 Mesh、高度页表、水色和宽度 | 贴地河面 |
| `river_bottom.shader` | 河底 Mesh、河床纹理和深度参数 | 河床颜色与水下深度感 |
| `CK3MapName.shader` | 曲线字形 Mesh、字体距离场、高度页表和纸面噪声 | 贴地地图名称与描边 |
| `CK3TreeSurface.shader` | 树木 Mesh、diffuse、normal、tint 和实例矩阵 | 双面裁切树叶与实例颜色 |
| `CK3DecorationSurface.shader` | 建筑 Mesh、diffuse、normal、properties 和实例矩阵 | 城堡、城市、神殿等实体装饰 |
| `CK3TabletopSurface.shader` | 桌面子网格与原版材质纹理 | 桌体、桌布和道具 |
| `CK3SurroundMap.shader` | 外侧遮罩、淡出图和 Flat Map 状态 | 世界矩形外侧画面 |

### 14.2 Terrain 是主要合成层

Terrain Shader 承担的内容最多，因为自然地表和政治地图必须严格使用同一世界坐标：

```text
节点局部坐标
  → 世界 XZ
  → 高度页表得到 Y
  → 四层地表材质混合
  → 宏观颜色
  → 政治颜色 Pre-Lighting
  → 地图光照
  → 政治颜色 Post-Lighting
  → Flat Map 过渡
```

省份 ID、政治颜色和距离场都只改变地表像素颜色，不切割 Terrain Mesh。地形几何、自然材质与政治覆盖因此始终保持同一位置。

### 14.3 几何覆盖层

边界、河流和名称都先在 CPU 阶段生成 Mesh，再由 Shader 绘制：

- 边界 Mesh 保存连续路径、宽度和笔刷 UV。
- 河流 Mesh 保存中心线扩展后的左右岸与沿河 UV。
- 名称 Mesh 保存每个字形沿曲线变换后的顶点与字体 UV。

这些 Shader 不负责重新分析行政区域或河网。几何阶段解决“在哪里、什么形状”，Shader 解决“什么颜色、怎样混合、如何贴合地形”。

### 14.4 实例装饰层

树木与建筑使用普通三维 Mesh，但位置来自实例矩阵。树木使用双面 Alpha Cutout，建筑使用背面剔除和不透明深度。两者都写入深度，因此近景物体之间可以正常遮挡。

距离淡出通过 Shader 抖动裁切完成。Renderer 只改变整体可见度，不需要逐个删除实例或替换模型。

### 14.5 深度、混合与剔除

| 地图层 | 深度写入 | 深度测试 | 混合/裁切 | 剔除 |
|---|---|---|---|---|
| Terrain | 开启 | `LEqual` | 不透明 | 背面 |
| 桌面 | 开启 | 正常测试 | 不透明或材质裁切 | 按材质 |
| 树木 | 开启 | 正常测试 | Alpha Cutout | 双面 |
| 建筑 | 开启 | 正常测试 | 不透明/抖动裁切 | 背面 |
| 海洋 | 关闭 | `LEqual` | Alpha Blend | 背面 |
| 河流 | 关闭 | `LEqual` | Alpha Blend | 双面 |
| 边界 | 关闭 | 开启 | Alpha Blend、模板限制 | 按边界 Pass |
| 名称 | 关闭 | `Always` | Alpha Blend、模板限制 | 双面 |
| Surround Map | 关闭 | `Always` | Alpha Blend | 双面 |

不透明层先建立颜色和深度，透明水体与河流随后覆盖，边界和名称最后提供地图信息。贴地透明层使用轻微高度或深度偏移，避免与 Terrain 处于同一深度时发生闪烁。

### 14.6 绘制顺序

完整画面的主要顺序为：

```text
桌面与世界外侧环境
  → Terrain 不透明地表
  → 树木与建筑
  → 水面与河流
  → 行政边界
  → 地图名称
  → URP 后处理
```

顺序的核心目标是先建立实体表面与深度，再叠加透明水体和信息层。最终得到的不是若干互相独立的贴图，而是一组共享世界坐标、按照深度与混合规则组合的地图渲染层。
